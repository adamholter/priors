# Data, scrapers and index math

## The contract

`src/data/types.ts` defines everything: `Snapshot`, `Model`, `Variant`, `Benchmark`, `Observation`, `RawRow`, `Source`. Read it first.

- A snapshot is one gzipped JSON file per day in `data/snapshots/<date>.json.gz`, plus `latest.json.gz`. They are committed: the repo is the archive.
- `src/data/load.ts` loads a snapshot by date or the latest, passing it through `canonical-snapshot.ts` (repairs identities in older snapshots) and `share-strings.ts` (every observation's ids, source pages and scrape times point at one shared copy: 40% less memory, 25 MB to 15 MB per snapshot). It keeps the six most recently used snapshots in memory, the live one included; older dated files are read again when asked for.
- `src/data/columns.ts` lays a snapshot out for the engine (`columnsOf`, built once per snapshot object and rebuilt if a list is replaced or grows): benchmark and variant ids interned to integers, `at[variant * nb + benchmark]` pointing at a row, and each row's value, flags and harness in typed arrays. When a cell has several plain measurements under different harnesses (ARC's Provider Adapter, Terminal-Bench agents), the best one is the cell's value, whatever order the source listed them in. `observationsOf` gives one benchmark's observations, for code reading a few hundred rows of plan or task data.
- `/api/snapshot?view=core&packed=2` is what pages fetch: `coreSnapshot` (no published intervals or ranks, which only benchmark pages show) as columns (`src/data/packed-snapshot.ts`: benchmark, variant and page named by index into shared lists, other fields as sparse columns with repeated strings kept once), about 2.6 MB of JSON against 8.9 MB plain. `packed=1` and no parameter return plain `clientSnapshot` JSON, for tabs on an older bundle and outside readers.
- `src/data/client-snapshot.ts` trims a snapshot for the browser (no scrape times, notes or raw details; source-model metadata cut to the fields the browser reads).
- The pages that calculate (builder, compare, 3D, and model pages when a visitor needs more than the standard rankings) load that dataset in the browser through `src/components/use-core-snapshot.ts`: one fetch and one parsed copy per tab, shared as the visitor moves between them, refreshed after five minutes. Never pass a whole snapshot as a server component's prop: it is serialized into the HTML (a model page was 21 MB). `scripts/verify/memory.mjs` measures each page's heap, DOM and bytes against a running build.

## Model identity

`src/data/normalize.ts` turns a source's model label into a canonical model id and reasoning effort.

- Regex families plus exact `ALIASES`. Unknown labels are excluded, never guessed.
- A variant (model + reasoning effort) is the ranked unit. When a source gives no effort, the row goes to the model's highest known effort.
- `none`, `minimal` and `low` are distinct efforts. Explicit model sizes (Qwen 27B versus 35B-A3B), Instant variants and dated DeepSeek revisions stay distinct too.
- `preview` is normally noise in a label, because a preview and its release are the same model. Hy4 is the exception: `hy-4-preview` and `hy-4` differ in weights, vision and scores.
- A generation number is a new model: `Inkling 2 Small` (594B) is `inkling-2-small`, never the original 975B `inkling`.
- Vals lists Meta's models without the brand: `Wonder` and `Wonder Full` are `aa-muse-wonder` and `aa-muse-wonder-full` (exact labels in `VALS_PUBLISHED_MODELS`).
- The catalog keeps models and variants a source stops listing (`retain-catalog.ts`). A retained model or configuration with no rows whose labels all resolve to another current model is a trace of a moved label and is dropped, so a split (Inkling 2 Small off Inkling, Carbon off Argon) leaves no stale configuration or orphan twin behind.
- `preview` stays a distinct model for o1 too: `o1-preview` (Sept 2024) is not `o1` (Dec 2024).
- A full DeepSeek date names a checkpoint (`deepseek-v4.1-flash-20261017` is `deepseek-v4.1-flash-1017`); the launch checkpoint keeps the bare id (`FIRST_CHECKPOINT`: V4.1 Flash launched as 0910).
- A thinking budget in tokens is a setting, never a version (`claude-3-7-sonnet_thinking_1024` is Sonnet 3.7). LLM Chess keeps each budget as its own configuration, as ARC does, and the no-budget Claude row is thinking off.
- **Release dates:** a source's own record for exactly that model (AA's canonical record, not a dated configuration) beats a leaderboard row's date; otherwise the first source's date stays (`applyDateHint`). Then overrides and OpenRouter fill the gaps. `RELEASE_DATE_PINNED` beats every source, each with its reason (Mistral Large 4: public on the API Oct 6, AA dates its Oct 29 open weights). Catalog retention drops a model's old date when one of its labels moved to another model, and a carried row follows its source record to its current variant. A carried row keeps only its first "carried from" date.
- Codenamed tiers are distinct models: GPT's Sol, Luna, Terra and Astra, and Gemini 4's Carbon (`gemini-4-carbon`). Gemini 4 Argon came first, so it keeps the bare `gemini-4` id.
- A label that is not one released model is unknown, never filed under the nearest name: a router (`gpt-6-auto (astra+luna)` sends each task to Astra or Luna, and read as a bare GPT-6) and an unreleased `Early` build (`Qwen-4-27B-Early` took the id the release will get).
- Lab colors live in `LABS` in `normalize.ts`: same lab, same color everywhere.
- Regression corpus: `scripts/benchmarks/` (`npm run benchmark:identity`, also run by Vitest). For a new parsing defect, add the source label and the independently reviewed identity to `fixtures/identity-cases.json`. Never edit expected groups to match the parser.

## Scrapers

`scripts/scrape/build.ts` runs every file in `scripts/scrape/sources/`, normalizes the rows and writes the snapshot. Raw payloads go to `data/raw/` (gitignored).

```
npm run scrape -- --date YYYY-MM-DD [--only aa,openrouter]
```

A full run takes 2 to 3 minutes (some sources use headless Chromium). A partial `--only` run keeps the other sources' rows and observation notes unchanged, even when their previous scrape failed, and seeds effort attribution from the previous snapshot.

To add a source, copy `sources/_template.ts`. Its header lists the rules: discover rows live, prefer structured payloads over DOM scraping, emit the label exactly as the site shows it, put a cost in `costUsd` only when the site reports measured run cost, save every parsed payload in `raw`.

Every benchmark comes from a live scraper. No frozen datasets are merged at load time. `liveBenchmarkId` in `src/lib/url.ts` maps the ids of a removed September 2026 import (`real-index:*`) in old shared links to the live benchmarks.

### Launch figures for new models

**AA speed (Performance Benchmarking v3.0.0).** From the Nov 4, 2026 snapshot, `aa-output-speed` and `aa-ttft` read `headline` (full-duration speed, averaged across workloads over 5 days, endpoint failures count as 0); before that, `timescaleData` medians. AA's time per task (`details.estimatedDecodeSecondsPerTask`, an old name kept so older snapshots still read) is computed, tokens divided by that speed: it matches `intelligenceIndexOutputTokensPerTask.output / headline.outputSpeed` exactly, is not timed, and leaves out tool time. `src/data/series-breaks.ts` lists such method changes: `/history` marks them when the index weights that benchmark, benchmark pages note them, and captions change with the snapshot's date. Add an entry whenever a publisher redefines a number.

**API default effort.** `Variant.apiDefaultEffort` comes from `defaultEffortHighlightedIds` on AA's home page. AA lists leading models only, so unset does not mean a variant is not the default. **Endpoint errors.** `aa-endpoint-error-rate` reads `/leaderboards/providers`, only for models whose speed comes from the lab's own API, as that is one published endpoint. A model reported as a median across providers has no row. The per-endpoint numbers are in the raw `endpoint-error-rates.json`.

`scripts/scrape/launch-claims.ts` holds the scores a lab publishes in its launch table, for boards that have not run the new model yet. Before adding a row, compare the reference models in the lab's table with the board's own values: if they differ, it is a different harness or version, so leave the row out. Each entry maps the table's rows to benchmark ids Priors already tracks (same version and harness as the board; rows that differ or that nothing tracks are left out). `build.ts` adds a score only while the board's own data has no result for that model at any effort, so the board's number replaces it the day it appears, whatever it says. These rows carry `details.launchClaim` and a note, and the benchmark page tags them "launch". The build log lists claims the boards have superseded (`LAUNCH_CLAIMS superseded`); delete an entry once all its boards have the model. AA's own announced results stay in `aa-preview.ts`.

### Subscription cost

`sources/realapipricing.ts` reads `derived/points.json` from github.com/FeiZhuLulu/real-api-pricing into the proxy benchmark `subscription-token-price`: plan fee divided by monthly tokens on the lab's own plan (median first-party plan; `low`-confidence rows are a last resort). Models with no first-party plan fall back to the best reseller or harness plan (OpenCode Go, Command Code, Droid, Ollama): lowest token price at medium confidence or better, since the list price is the same on every plan, so cheapest tokens means biggest subsidy. `sources/subscription-overrides.ts` holds curated figures read from a plan page that states its allowance in dollars (Muse Wonder on Command Code Max at 1.5×; Gemini 4 Argon's OpenCode Go promo figure was retired on 2026-10-28 once Real API Pricing measured Google AI Pro, whose slug `gemini-4-argon` maps to Priors' `gemini-4` through `PRIORS_IDS` in `realapipricing.ts`). They carry `ratio` directly, replace any computed row, and need about 80% confidence and a checked date. One is a published measurement, not a plan page: Claude Fable 5.2 on Claude Ultra, at 4.85 times Opus 5.5's share of API price (7.3%), from one Max 20x account's week ($705 of Fable 5.2 from its half of the weekly limit against $3,421 of Opus 5.5; x.com/theo/status/2119960608816988596, checked 2026-11-10; two other accounts give 3.6 and 5.1 times). Real API Pricing had no Fable 5.2 row then, and its first sample (pull request 228) leaves out Fable's half-week cap, which would read 4.0%; remove the override once its row applies the cap. `SUBSIDY_ASSUMPTIONS` in the same file covers models no plan sells yet by assuming another model's subsidy: Gemini 4 Carbon gets Argon's Google AI Pro row (Google opened Carbon to cyber defenders first; subscriber access is "coming soon"), with its plan labelled "assumed same as Argon" and confidence `assumed`. The row carries `sameAs`, so `src/data/subscription.ts` gives it Argon's share of API price even if the two list prices part; a measured row for the model replaces the assumption. `PLAN_CHANGES` in the same file corrects plans whose allowance changed after Real API Pricing measured them: older measurements are rescaled to the current allowance (ChatGPT Pro $100 doubled from 5× to 10× Plus on 29 October 2026; the Pro $200 cut to 10× announced on 29 September was canceled that day, so Pro $200 stays at the 20× Real API Pricing measured, and both Pro tiers give twice Plus's tokens per dollar). `PLAN_MULTIPLES` derives a plan sold as a multiple of a measured one for models measured only on the base plan (or only at low confidence on this one): ChatGPT Pro 10x and 20x from Plus, one confidence grade lower, as Real API Pricing derives its own Pro rows. That keeps every OpenAI model on the same median plan (Pro 10x) instead of leaving the ones measured only on Plus at twice the price. `BUDGET_PLANS` covers plans sold as a monthly dollar budget spent at the seller's own API rates, which Real API Pricing has not measured: each listed model gets a point computed the way Real API Pricing computes one (fee ÷ the tokens the budget buys at the seller's rate for that model, standard workload; no list price, so the model's own lab's price, or Artificial Analysis', prices the API side). Mistral Vibe Pro ($14.99) has a $300 Vibe budget at Mistral's rates, as a Pro account shows it (Mistral does not publish the figure; reported 29 October 2026), plus $25.50 of API credits from the pricing page, so medium confidence. It is the first-party plan for Mistral's models and a reseller plan for the GLM and DeepSeek models Mistral hosts: the price for one with no first-party plan when it is the cheapest (GLM 5.2), and listed among the plans of one that has a first-party plan (GLM 5.3) so it can be picked under Advanced → Plan. A Real API Pricing point with the same id replaces the curated one. Meta's own Muse Code plans publish prompts per 5 hours, not tokens, so they cannot be priced. Free tiers come from `scripts/scrape/free-tiers.ts`, not from overrides: every run reads OpenCode Zen's live model list (ids ending `-free`) and OpenRouter's (`:free` variants), and `src/data/free-tier.ts` turns each listing that names a ranked LLM, by exact name, into a ratio 0 row for that model, replacing any computed one. OpenRouter prices some image, audio and router entries at 0 in odd ways, so a listing must output text only, have every price at zero, and not be a router or a safety, guard, moderation or embedding model; entries that match no ranked model are ignored. A model drops off when the provider drops it, so nothing needs removing by hand. If a list cannot be fetched, the previous snapshot's free rows are carried forward. `src/data/subscription.ts` divides the token price by the API list price at the same workload to get each model's share of API price. Plans that sell a monthly budget Real API Pricing has not measured live in `BUDGET_PLANS` (Mistral Vibe Pro in dollars, Tencent's Token Plan in credits against Hy4's USD list price); a promotional rate applies until its stated moment, then the standard rate takes over without a change here.

An OpenAI model Codex lists (`sources/codex-limits.ts`, the Plus column of learn.chatgpt.com/docs/pricing, into the proxy `codex-plus-messages`) with no plan data yet pays the median share of API price of the listed OpenAI models that have been measured, labelled `estimated from the median share of ...`. Its own plan row replaces this. `npx tsx scripts/verify/subsidy-backtest.ts` tests the choice: it hides each independently sourced row in Real API Pricing and predicts it from the plan's other non-derived rows. A row computed upstream from another row is never used as an answer or as an input, because that grades the method against itself. Estimates of a new model miss by about 1.5x typically under every sibling rule tried, so read them as a range.
**Token mix.** `sources/slopalytics.ts` puts each model's measured mix in `t3-usage-share`'s `details.tokenMix`: its shares of all tokens (cache read, fresh input, cache write, output) over the export's last 7 days, on the harness with the most usage, with other measurable harnesses in `byHarness`. It needs 1B tokens and 1,000 turns in the window; 100B makes it `high` confidence, otherwise `medium`. It refreshes with every scrape. `tokenPrice` blends list prices at that mix, falling back to the plan's assumed mix, and the model page shows the result with the dates and confidence. A plan's share of API price deliberately does not use it: the plan's token price was converted at the plan's mix, and an allowance spent at list prices gives the same share at any mix, so cost per task doesn't move. The Codex-limits estimate compares two models' prices, which does depend on the mix, so it uses each model's measured mix. The mix describes T3 Code users only. It can't say why a mix changed: Codex's permanent caching has no known launch date in this data.

**Limit resets.** A lab now and then refills everyone's weekly allowance early, which is extra usage on top of the plan. `scripts/scrape/plan-resets.ts` keeps each lab's reset history in `snapshot.planResets` (not a benchmark: it prices plans, never ranks): OpenAI from OpenTheRank's Codex reset tracker (opentherank.com/codex-reset; Tibo's, every reset a `cx-stamp` element with an ISO time and type), Anthropic from claude-resets.com's `data/resets.json` (CC BY 4.0; unofficial, entries link the ClaudeDevs posts; its `policy` entries are limit changes, not resets). `build.ts` runs it after the free tiers, always carries the last history forward, and replaces a lab only when its source was read: a changed page throws instead of reading as "no resets". `src/data/plan-resets.ts` turns it into the adjustment, over the 30 days before the snapshot (`generatedAt`). The two labs' resets do different things to the weekly clock, so they are valued differently: Claude's "weekly limits still reset on their usual day and time" (Claude Help Center, "What is a limit reset?"), so each reset is a whole extra allowance (+1 week); an OpenAI reset moves the weekly reset date and the next one comes 7 days later (Codex help), so it replaces the rest of the old week and adds only 1 - x of an allowance, x being how far into its week the reset landed (the previous reset, then a 7-day clock from it, so it is worked out from the real reset times). 12 Codex resets in the last 30 days, 1 to 5 days apart, add 7.5 weeks. Both assume the plan prices' own premise, that the subscriber spends every allowance. **Banked resets are not counted** (applied at the user's own time to make up for the gaps, so counting both would count the allowance twice), nor are resets only some users got. A lab's plan share of API price is divided by `1 + extraWeeks / (30/7)`: 2.75× for OpenAI today. It is **off by default** (Adam, 2026-10-28): the engine applies it on the subscription basis only when turned on (`config.planResets === true`; "Count limit resets" under Advanced in chart settings, remembered per browser once turned on (`priors:plan-resets` = `on`, `src/lib/plan-resets-pref.ts`; applies to every page until turned back off), `resets=on` in links, `planResets: true` in stored configs and MCP; older configs' `planResets: false` and links' `resets=off` read as the default), notes it in the cost source ("with 12 limit resets in 30 days"), and the settings panel says what is counted. Claude's plan, at the time of writing, has had no regular reset for over 30 days, so its price is unchanged.

**Parameter counts.** `paramsB` is the count the lab states on its model card or launch post (`STATED_PARAMS` in `src/data/open-weights.ts`), the figure it compares its own models by. Models it lists have a `paramsNote` saying what the number is, and it comes back through the MCP tools. Everything else keeps Artificial Analysis' count, which is Hugging Face's safetensors total: what the files hold, which can sit either side of the lab's figure. Inkling Small: 276B stated, 266B in the files. DeepSeek V4.1 Flash: 552B backbone stated, 763B in the files, which add 196B of Engram memory.

**List prices.** A plan's share of API price needs the lab's own price today. Real API Pricing's list price comes first. A budget plan's rates are the list price on the seller's own model, since the budget is spent at them. `LIST_PRICES_UNTIL` holds a lab's price for a stated period that Artificial Analysis does not list (Gemini 4 Argon at $2/$10 through November 30, 2026, $4/$20 after), and the row falls back when the date passes. Artificial Analysis still priced its measured costs at its own list, so while one of these is in force those costs scale by `aaCostRatio`: the tokens at the plan's price, whichever list is quoted. On API pricing the chart shows Artificial Analysis' cost as published. A model assumed to match another's subsidy takes the share at full list price.

**Merged labels.** A family rule that matches `SWE-2` and ignores `Flash` files a new model under an old one. `scripts/scrape/label-collisions.ts` reports it two ways: `labelCollisions`, a row the build's keep-first dedupe drops because a label with different tier words holds it (SWE-2 Flash's max row), and `swallowedTiers`, a label naming a tier its model does not have, which catches it before any row collides. The build logs each as `MERGED_LABELS`. The job's first run records what exists as a baseline; after that each line it has not seen notifies once. Fix a real one in `normalize.ts`. Older merges are still in that baseline, such as GLM-5 Turbo holding GLM-5's rows on BSBench and ALE-Bench.

**Free tiers and OpenCode Go.** A model free today gets a ratio 0 row, and its paid row rides along as `details.paid`. `IndexConfig.freeTiers: false` (link key `free=off`, "Count free tiers" under Subscription plans) prices those models on their paid plans, or API price with none, and a plan picked for the lab beats the free tier either way. OpenCode Go's DeepSeek rows are read live from its docs (`parseOpenCodeDeepSeek`) for Go, Go Plus and Go Teams, replacing Real API Pricing's row: a limit is dollars at DeepSeek's own prices in the same hour, so the share is fee ÷ limit. The limits draw on one allowance, so a plan buys its Flash limit or its Pro limit, not both, and 20% of a limit per 5 hours and 50% per week also apply. An undated id serves the latest revision, so Flash's rows go on both DeepSeek V4.1 Flash and its 1017 revision.

**Speed tiers.** `scripts/scrape/speed-tiers.ts` keeps each model's Flex, Fast and Ultrafast in `snapshot.speedTiers` (not a benchmark: same model, same scores). `rates`: tier price and measured speed against that model's standard. Artificial Analysis benchmarks a tier as its own endpoint and wins where it has one; OpenRouter's first-party endpoints fill the rest, Opus Fast above all (three days of hourly medians, needing a day of hours and 100 requests on both sides; a Fast or Ultrafast reading slower than standard on thin traffic is left unmeasured, and keeps its price). A ratio is only ever taken within one source, because the sources disagree: on 5 November 2026, GPT-6.1 Sol Ultrafast was 4.3x on Artificial Analysis and 1.3x on OpenRouter. `planRates`: the tiers a subscription covers and how fast they spend the allowance, read from OpenAI's Codex speed doc (Fast 2.5x on any plan, Ultrafast 8x on Pro 500). A tier with no plan rate costs what the API charges under subscription pricing: Flex, which is API only, and Opus Fast, which Anthropic bills from usage credits outside the plan (the scrape logs if its doc stops saying so). Speed is measured on one effort and applied to every effort; `src/data/speed-tiers.ts` does the arithmetic. A source down for a run carries its rows over.

**ChatGPT Pro 500.** Listed in `PLAN_MULTIPLES` because it is the only self-serve plan with Ultrafast, at 50 times Plus: launched at 25 and doubled on 29 October 2026 (OpenAI publishes the doubling, not the 50). `listOnly` keeps it out of the median, so adding it moved no model's default price.

**Two readings of one plan rate.** A curated row in `SUBSIDY_OVERRIDES` can carry `readings` (id, name, ratio, one-line note); the first is the row's `ratio` and the default, and `IndexConfig.planReading` (link `reading=<id>`) picks another for every model that has it. Claude Fable 5.2 has two, both multiples of Opus 5.5's share on Claude Ultra from Theo's Max 20x account: `shared` (default since 2026-11-11) prices a Fable dollar at what it burns of the weekly limit it shares with Opus, $34.2 vs $14.1 per 1% of the week, 2.4267x or about 3.67% of API price; `own` counts only the Fable a plan can buy, $705 a week in its half vs $3,421 of Opus, 4.85x or about 7.3%, true only if the other half of the limit goes unused. Fable stops at half the weekly limit. `/api/plan-prices` lists both under `readings`; the MCP settings report the one in use.

**Renamed plans.** `PLAN_CHANGES` in `sources/subscription-overrides.ts` relabels Real API Pricing's rows when a plan is renamed (Claude Max 20x is now Claude Ultra). `FORMER_PLAN_NAMES` in `src/data/subscription.ts` keeps links, saved pages and browser choices made under the old name working.

**Which plan.** Each model is priced at its median plan unless the viewer picks one for its lab under Data → Subscription plans in a cost chart's settings (one select per lab with more than one plan in the data, from `subscriptionPlanOptions`; the choices are every plan in that lab's rows' `plans` list, by fee). `config.subscriptionPlans` maps lab id to plan name; `subscriptionPrices(snapshot, chosen)` then uses that plan's measured token price for every model of the lab that has it, and the median plan for any that does not. A model assumed to match another (`sameAs`) follows the plan that model is priced at. The choice is remembered per browser (`priors:subscription-plans`, `src/lib/subscription-plans-pref.ts`; a link's or page's choice for a lab wins), carried in links as `plans=lab:Plan%20name,...` (also in chart links' `hv`), and stored on saved pages (Convex validator `subscriptionPlans`).

Subscription pricing is the default: `IndexConfig.costBasis` unset means subscription (`effectiveBasis` in `src/data/subscription.ts`); only an explicit `"api"` is stored (URL `costbasis=api`, the Pricing toggle in the cost chart's settings). It multiplies measured cost per task by that share, so a free tier costs $0. Log cost axes have no 0: `costChart.points` puts free models a step left of the cheapest paid cost (`freeFloor`, a quarter of it) with `free: true`, tooltips and bar labels read "free", and the scatter draws a dashed "free" line there. Models without plan data keep API cost. It is a lower bound, because it assumes the full allowance is used. The toggle only shows when the snapshot has the benchmark.

### Open weights

`Model.openWeights` says whether a model's weights can be downloaded (any license); `paramsB` and `activeParamsB` hold parameter counts in billions when a source publishes them. `src/data/open-weights.ts` sets them at scrape time, from the most to the least trustworthy: `CHECKED_WEIGHTS` (repos checked by hand), Artificial Analysis's `isOpenWeights` in each variant's source metadata, flags other sources return in `modelFlags` (Epoch ECI's accessibility group, Benchmark Heaven), then `FAMILY_RULES` for families whose status never varies. Unknown stays undefined, which is not the same as closed. The build logs `OPEN_WEIGHTS n open, n closed, n unknown`. `/api/history` fills the flag on older snapshots from today's models, since a model's weights don't change. Charts: the history page's "Open vs closed" colouring and best-by-weights chart, and the assistant's `weights` filter.

## Index math

`src/engine/index.ts`. Tests in `index.test.ts`. The engine works on `src/data/columns.ts` and keeps each call's state in flat arrays (a cell is pool position × share); it opens an observation only to write out a full result. `rankVariants` does the arithmetic for both `computeIndex` and `rankScores` (scores alone, for history). `golden.test.ts` holds results byte for byte to `src/engine/fixtures/expected.json` (real data for one finished day, plus a small fixture with row shapes today's data lacks, and a lineup fit under a virtual clock). After changing the math on purpose, regenerate them with `npx tsx scripts/verify/engine-goldens.mts`, and check the diff is what you meant. The flow is drawn in `docs/ranking-logic.svg` (age filter, exclusions, measured share, Required gate, coverage floor, estimation, score). Regenerate the diagram when the gates change.

- **Scores are used as published.** Percent and fixed-scale scores are not rescaled (`FIXED_SCALES` covers snapshots without `normalization`). Nothing is stretched so the leader reads 100. Elo becomes win rate against the pool's median model. Other open-ended units go through a logistic around the pool median scaled by spread (USD in log space).
- **Cost means measured cost per task** (`aa-cost-per-task-index`, or a benchmark's `costUsd`). Never token price. `aa-price-blended` is `proxy: true`.
- **Effort matching** defaults to calibrated (`nearest` is a legacy alias). Exact results win. A missing effort uses the nearest measured effort, adjusted by the same model's ratio between those efforts on other benchmarks (ratio of means over the paired benchmarks). The ratio is capped at 4× either way and shrunk toward 1 by n / (n + 2) in log space, so one paired benchmark counts for a third of its size and 40 for nearly all of it. When the pairs say less effort scores higher (or more effort lower), there is no estimate: BullshitBench v2 scores Qwen 3.8 27B at 79 with no reasoning and 29 at max, and that ratio once put its no-reasoning Arena WebDev at 100. Without enough paired evidence the value stays missing. A maximum-effort score is never copied unchanged to a lower effort. Cost and speed are never effort-substituted. The donor value, source variant, multiplier and evidence are shown in the advanced Calculation settings; the main charts carry no estimate markers.
- **Strictness (0 to 100)** is the measured-coverage floor. A variant is ranked only when measured values (observed or effort-substituted; peer estimates never count) cover at least that share of the index's weight. 0 ranks anything with a value; 100 requires full coverage and disables inference. Strictness also sets the minimum number of effort comparisons, the allowed effort distance and the peer release window.
- **Required** benchmarks are hard per-benchmark gates. `optional` is a legacy field with no effect on ranking. `cutoff` survives for old URLs and derives strictness.
- **Missing values** above the floor are estimated from peers (release window, price tier) and marked, or the weights are renormalized when estimation is off. A peer estimate averages two guesses: the mix match (nearest models on the benchmarks in the mix, shifted by the average offset) and, for percent benchmarks, a panel match (models whose scores are closest as ratios across every measured percent benchmark they share, at least 8, scaled by the median ratio; reliability shares such as uptime are left out of that panel). Other models only; the target's own efforts never donate. Each estimate carries `donors` and an `estimateRange` (the donors' spread, never under 1.5 points), shown in the model detail and the bar tooltip. `scripts/verify/peer-backtest.mts` hides known scores and measures the miss: on the 2026-10-18 snapshot (168 hidden scores, 12 benchmarks) mean error fell from 7.5 to 6.5 points and 85% of hidden scores landed inside the range. Re-run it before changing the estimator. At strictness 50 and above, a model needs 2 measured benchmarks to seed estimates and peers need 2 shared benchmarks. The peer offset shrinks as `off/(n+1)`.
- **Versioned benchmarks** use `versionPolicy`: `fallback` (DeepSWE 1.1 falls back to 1) or `fresh` (AA index versions).
- **Defaults:** strictness 50. `releasedAfter` undefined means models released in the six months before the snapshot date; an empty string (empty `after=` in the URL) means all time. Models with unknown release dates are never age-filtered.
- **Chart modes are independent.** `rankingVariants` defaults to `best`, `paretoVariants` to `all`. Compute the full variant set once, then call `selectVariants` per chart. `efforts` filters the cost, time and speed charts through `filterEfforts`.
- **The default view drops superseded versions.** Pages that show an index call `computeIndex(..., PAGE_VIEW)`. When the index has no `excludeModels` or `onlyModels` (nobody curated it), `supersededModelIds` (`src/engine/superseded.ts`) leaves out an older version of a line (same lab, same name apart from the version number, newer one no older by release date) none of whose efforts is on the cost frontier. A model with no measured cost cannot be on that frontier, so it is judged by score alone: it goes when a newer version scores at least as well. Under AA's v5 index only the models AA has run v5 on carry a cost, so most older versions are judged this way. Scores do not change, `result.autoHidden` lists them, the picker shows them unticked, and "All" is `excludeModels: []`, an explicit choice that turns the rule off. Internal callers (solver, optimizer, history) never pass `PAGE_VIEW`.
- **The release-date chart places models the index cannot score.** AA runs its current evaluations only on recent models, so under the v5 index most older ones fall below the coverage floor (`excluded`, reason `coverage`) yet stay in the highlight menu. `progressEstimates` (`src/engine/progress-estimate.ts`) fits log(score) = a + b × AA Progress Index over the ranked efforts that have both (at least 8 pairs, R² ≥ 0.9, about 0.99 on the v5 index) and gives each such model an estimated score (`result.estimated`, `RankedVariant.scoreEstimate`); never above the highest paired Progress Index, never for a model the index scores or a benchmark the user required, and in a default view not for a superseded version unless highlighted. Only the release-date chart draws them, as rings labelled "est.", with the fit in the point card. Nothing ranks them, and the assistant's tools never see them.

## History

`/api/history` and the assistant's `index_history` call `computeHistory` (`src/lib/history.ts`): today's index on every snapshot date. It reads `data/snapshots/history.bin.gz` (`src/lib/history-archive.ts`), one columnar file with what a ranking reads from every dated snapshot: shared score rows plus a patch per date, walked forward through one `Columns`. Today's frame comes from the live snapshot. A date the file lacks is read from its dated snapshot, and with no usable file (absent, damaged, another `VERSION`) every date is, so the file costs nothing to lose but time. **Change `VERSION` when the format changes.** The file is generated, never committed: `build.ts` writes it after each scrape, `npm run build` writes it first from the checkout (`prebuild`; Vercel's `buildCommand` runs it too), and `scripts/ops/daily-scrape.sh` publishes it to `data-live`.

## Index configs and URLs

- `IndexConfig` is defined in the engine. `src/lib/url.ts` encodes it into one `i` query param per index: `?i=name|bench:w,...|req=|strict=|bars=|pareto=|est=|var=|effort=|labs=|ex=|only=|after=|tier=`. Several `i` params mean several indices.
- Links are written through `prettyQuery`, which keeps `:`, `,` and `=` readable; both forms decode the same. `page=handle.id.key` marks the published page index a builder index was opened from. It is written only to the builder's own address and the owner's "Open in builder" links, rides along at runtime (`FromPage`), is trusted only with the key held in that tab's sessionStorage, and is never stored.
- Stored configs (profiles) are validated by `convex/validators.ts`. `IndexConfig` is asserted exactly equal to the validator at compile time, so adding a field on one side without the other fails `tsc`. Every write goes through `storableIndex()`, which drops transient keys. `src/lib/stored-index.test.ts` checks every config producer.
- Model visibility is stored as whichever is shorter: `excludeModels`, or an `onlyModels` allowlist once more than half the picker is hidden (new models then stay hidden). Hiding a model is the user's choice and reversible: excluded models can be re-checked in the chart-settings model picker.
- `src/lib/import.ts` is the zod schema for user and agent benchmark imports, and merges them into a snapshot.


## Benchmark pages

`/benchmarks` is a searchable directory (`src/components/benchmark/BenchmarkDirectory.tsx`): a category rail on the left, and rows whose values line up under labelled columns (top model, models, mixes, quality), with a short-delay tooltip on each. Search is loose (`searchBenchmarks(..., { loose: true })`): names outrank descriptions, every matched word counts before score, one typo in a name word is forgiven, and description words match by stem. The default order is recommended: quality (`qualityOf`, the onboarding's score) lifted by popularity (published pages with any index that weights it): `quality + 12 * log2(1 + uses)`. Older versions and category splits are hidden until asked for, and searched always. `/benchmarks/methodology` explains quality and recommended; it reads `QUALITY_WEIGHTS`, `QUALITY_ADJUST` and `USE_LIFT`, so the page cannot drift from the math. The top model is the best score the publisher reports, older models included, never an estimate. Publisher icons load from DuckDuckGo's icon service, which the privacy page discloses.

`/benchmarks/<id>` is one benchmark's page (`src/app/benchmarks/[slug]`). The address is the benchmark id; looser forms such as `frontier-code-2` redirect to it (`src/lib/benchmark-slug.ts`, the current non-variant version wins). The page ranks models by that benchmark alone (`src/lib/benchmark-page.ts`) and only shows what the benchmark published: rows Priors estimated, fallbacks to an older version and calibrated routes from other benchmarks are stripped from its trimmed snapshot. Older versions and category splits are their own pages, linked from the Version and Category menus (`benchmarkRelatives`, following `supersedes` and `fallbackTo`).

Charts plot the benchmark's published value (dollars, Elo, percent) through `ScoreAxisContext` (`src/components/chart/score-axis.ts`) when higher is better; lower-is-better benchmarks keep the Priors scale. Everything else a source publishes is discovered from the observations (`src/lib/benchmark-metrics.ts`), not listed per source:
- per-task measurements (`steps`, `durationSec`, `outputTokens`) get their own score-vs-metric charts;
- every number under `details` (sub-scores, splits, counts, rubric rates) is a measure in "Score vs any published measure", and siblings under one parent (split by kind) form the Breakdown table;
- scraped `series` (Vending-Bench 2 money balance by day, from Andon's page bundle) and per-model number lists in details become line charts.
Run settings and interval bounds are skipped (the `SKIP` list). When the benchmark publishes cost per task, the cost chart uses it (`ViewOptions.costBenchmark`) with the same subscription adjustment as every other chart. The shared client snapshot drops `series` and most `details`; the benchmark page's own snapshot keeps them for its benchmark.
